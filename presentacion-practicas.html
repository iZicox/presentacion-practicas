Prácticas FP · Desarrollo de Aplicaciones Web 03 — Solución
Arquitectura de la solución

Cómo encaja

Cliente Entra en la web y se identifica
WordPress + Elementor Comprueba la sesión y llama al Worker
Worker Cloudflare Service token de Cloudflare Access
ERP GET /producto/:id solo lectura, vía túnel

Flujo: navegador → WordPress → Worker → túnel → API del ERP, sin abrir puertos a internet ni que el navegador hable con el Worker. En la ficha, el shortcode [stock_api] pide el dato con caché de 15 minutos.

Prácticas FP · Desarrollo de Aplicaciones Web 03 — Solución
Área privada de cliente

Login e inventario

Paso 01

Se autentica

El shortcode comprueba is_user_logged_in(): sin sesión no se llama a la API.

Paso 02

Llama al Worker

WordPress envía las cabeceras CF-Access-Client-Id y CF-Access-Client-Secret.

Paso 03

Ve el stock

El Worker consulta el ERP por túnel y devuelve la disponibilidad.

Autenticación definida: Cloudflare Access con service token entre WordPress y el Worker (secreto en wp-config.php). Si la página se cachea, el shortcode pinta un contenedor vacío y el dato llega por un endpoint REST con permission_callback.

Prácticas FP · Desarrollo de Aplicaciones Web 03 — Solución
Implementación · Filtros del catálogo

Filtrar productos

  • 01 Slider doble de rango para el atributo Size Shortcode [filtro_rango_size] con jQuery UI Slider: genera ?size_min=20&size_max=60.
  • 02 Filtrado en la consulta principal Tax_query en woocommerce_product_query, conservando el resto de parámetros de la URL.
  • 03 Plugin propio luc-product-filter Los plugins existentes cobraban el filtro de rango; se optó por crear uno propio.
  • 04 Próximo paso: el resto de atributos Ampliar el código del slider con los demás atributos en casillas de verificación.
